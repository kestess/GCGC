# GCGC in Rust + WebAssembly

A port of [GCGC](../README.md) (Garbage Collection Graph Collector) from a Python/Jupyter notebook to a
Rust engine compiled to WebAssembly, with a static web front end. Drop JVM GC logs into the page
and get the notebook's analyses: STW pauses, latency heatmaps, percentiles, heap, allocation rate,
code cache, metaspace and summaries. Everything runs locally in the browser; nothing is uploaded.

## Quick start

```bash
# one-time tooling
rustup target add wasm32-unknown-unknown
cargo install wasm-bindgen-cli --version 0.2.100

./serve.sh            # builds, then serves the repo root on http://localhost:8765
open "http://localhost:8765/gcgc-rs/web/?examples"
```

`?examples` loads the seven example logs from `../datasets/` (the same ones the notebook uses).
Without it, drop your own logs (`-Xlog:gc*:file=gc.log`) on the page. Rotated files such as
`gc.log.0` and `gc.log.1` are merged into one run automatically.

To get a self-contained static site (for GitHub Pages, S3, an internal server and so on):

```bash
./build.sh --dist     # writes dist/ (app + wasm + Plotly + example logs, ~5.5 MB)
```

The site must be served over HTTP(S). Browsers don't load WebAssembly modules or module workers
from `file://`.

## Layout

```
crates/gcgc-core/   pure Rust engine (no I/O, no wasm dependencies)
  parse.rs          the GC log regex (built term-by-term like parse_log_file.py) → typed columns
  run.rs            per-run derived columns: time scaling, heap %, metaspace MB, code-heap %, zeroing
  table.rs          small column store replacing the pandas DataFrame
  query.rs          declarative filters and group-by (filter_and_group.py)
  plotting.rs       ports of src/graphing/*.py; record matplotlib-style calls on an Axes
  analyses.rs       the notebook's 21 numbered analyses + tutorial + custom chart, with UI parameters
  stats.rs          numpy-exact sum/mean/std/percentile/round
  npsort.rs         numpy introsort emulation (reproduces pandas' unstable sort_values order)
  pyfmt.rs          CPython float repr / round / "%9.4f"
  csv.rs            CSV reader for the external-data overlay
crates/gcgc-wasm/   wasm-bindgen Session API (JSON in/out)
web/                index.html, app.js (UI), worker.js (engine in a Web Worker), render.js (→ Plotly)
```

## Fidelity to the original

The engine is tested against **golden outputs recorded from the original Python code**: Python 3.9,
pandas 1.5.3, numpy 1.24.4, matplotlib 3.7.5, generated by `../port-notes/tools/make_golden.sh`.
See [../port-notes/golden.md](../port-notes/golden.md).

```bash
../port-notes/tools/make_golden.sh   # once; needs the venv described in port-notes/golden.md
cargo test --release
```

What the tests check, all **exactly** (bit-identical floats, byte-identical text):

- the generated regex string, and the raw captures for all 41,958 matching lines in `datasets/`
- the parsed table for each of the 18 logs, and the full per-run tables after loading and after the
  notebook's in-place sort, for all three notebooks
- every code cell of `GCGC.ipynb`, `FeatureExamples.ipynb` and the universal-plotting tutorial (47 cells).
  For each one: every `plot`/`scatter`/`bar`/`imshow`/`text` call with its data, labels, colours,
  alpha, marker and width, plus legends, explicit ticks, y scale, figure count, and the exact
  printed output (ASCII tables, warnings)

The wasm build's output was also compared with the native build for every analysis and is identical.

To eyeball it yourself, run `./serve.sh` and open **http://localhost:8765/gcgc-rs/web/compare.html**.
It shows each notebook cell's original matplotlib figure and printed output (from `port-notes/golden`)
next to the WebAssembly engine's chart computed live from the same logs.

### Intentional differences

| Area | Original | Port |
|---|---|---|
| Inputs | `glob` paths in a notebook cell | Files dropped in the browser. Wildcard groups become rotated-file runs, sorted by name (the original's glob order depended on the filesystem) |
| Filters | arbitrary Python predicates | declarative JSON filters (`eq`, `in`, `not_null`, `truthy`, `contains`, `and`, `or`, `not`, `all`) that cover every predicate the notebook uses. Plus a *Custom chart* card for ad-hoc views |
| `ignore_crashes=True` | raises KeyError | implements the documented intent (applied after time scaling) |
| Empty runs | silently dropped, which shifts labels | kept as empty runs |
| Python exceptions | traceback in the cell | the analysis shows an error message |
| `plot_pie_sum`, `include_timing_in_bucket` | broken | not ported |
| A few titles | "…LOG scaling", stray `“`, a copy-paste title in #21, "Sum of seconds" (it is ms) | corrected |
| Rendering | matplotlib PNG | interactive Plotly (zoom, hover, PNG export) |

Original behaviour that is reproduced on purpose (documented in `../port-notes/README.md`): the
`"Mixed"` heap-percent comparison never matches, empty intervals count as 1 GC in #20, labels in
#9 come from the run labels rather than the group labels, and `round()` follows numpy semantics
for grouped series.

## Performance

On the example logs, parsing all seven runs takes about 0.17 s in the browser. A synthetic 116 MB log
(208k events) parses in about 3.3 s in wasm, and each analysis renders in under 0.5 s. A literal
prefilter skips the backtracking regex on lines that can't match; it doesn't change results, which
the golden tests confirm.

Sizes: `gcgc_wasm_bg.wasm` is 1.9 MB (≈600 KB gzipped). Most of that is the Unicode tables needed to
match Python's `\w`/`\d` exactly. The Plotly cartesian bundle is 1.36 MB (≈445 KB gzipped).
